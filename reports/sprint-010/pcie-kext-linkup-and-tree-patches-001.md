# PCIe bring-up in the kext, MSI from the bridge, PureDarwin tree patches (2026-11-09)

Boots `m01`, `m02` (lab build) and `p01` (built from the tree patches) on the J293 under the
m1n1 hypervisor; all three end with the same full result (WPA2 join, DHCP, ping, HTTP, lookup
by name) and the M1 returned to Linux after each. Console: `runs/m1-desktop-010/pcie-enum-attempt-p01/`.

Link bring-up in the kext (`PDApcieT8103Link.cpp`, ported from m1n1 `pcie.c`/`pmgr.c`/`tunables.c`
and the proven link sequence):

    PCIE_LINKUP {"mode": "kext", "radio_power": true, ...}        (launcher: one SMC write only)
    PDApcieT8103: state: phy ctrl 0x00000080 phyif ctl 0x00000000: PHY not running; port not read
    PDApcieT8103: link: running the whole controller, PHY and port bring-up
    PDApcieT8103: phy: up, 11 fuse fields applied; phy ctrl 0x0000000f phyif ctl 0x00000001
    PDApcieT8103: link: port0 link up; linksts 0xdb000001, root port lnksta 0xb812 (speed 2, width 1)

The kext starts from a cold controller (power domains, nine tunable lists, PHY, port, PERST#,
refclk, MSI block, link training) and the link trains at 5 GT/s, as under Linux; the launcher
sequence only reached 2.5 GT/s. The launcher still does one thing: the SMC `gP0d` radio-power
write. `PCIE_LINK=kext` selects this mode in `tools/pcie_iterate.sh`; the default is still the
launcher doing everything.

MSI from the bridge: drivers call the platform function `PDApcieSetupMSI` on their PCI nub; the
host bridge allocates a message, programs the device's MSI capability and describes the AIC
interrupt on the client.

    PDApcieT8103: msi: 1:0.0 message 0 -> AIC interrupt 704 (doorbell 0xfffff000) for PDBwfm

Board identity: `PDBwfm: board type apple,honshu (device tree), antenna SKU X0 (device tree)`.
The DART stream stays a constant (1); the Apple device tree does not carry it and Linux
hard-codes the same value in its device tree source.

PureDarwin tree patches (`integrations/puredarwin/puredarwin-patches/`, generated by
`tools/pcie_export_patch.sh` against e7aa00a6):

- `0001-m1-pcie-wifi-kexts.patch`: `src/Kernel/Extensions/PDApcieT8103Bridge`, `PDBwfm`, CMake.
- `0002-m1-pcie-wifi-userspace-and-registry.patch`: `src/Userspace/pd-dhcp` (with `pd-net-up`),
  and the `nix/lib/kexts.nix` entries.

Both apply and build in-tree (`build-from-patch.nix`, `build-userspace-from-patch.nix`), and
boot `p01` used the kexts and `pd-dhcp` built that way (`PCIE_FROM_PATCH=1`). Not verified: the
`nix/lib/kexts.nix` hunk (that file is not in the filtered build source) and adding the kexts
to PureDarwin's own arm64 kernel-collection list. The patches are not submitted anywhere.
