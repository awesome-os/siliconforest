# Native resolver prerequisite001

Install the built upstream daemon as `/usr/sbin/mdnsd` and original probe as `/usr/bin/darwin-resolver-probe`. Start the daemon with exactly `-debug`: this keeps the real POSIX daemon in the foreground. This leaf does not create resolver files, launch services or execute either Darwin program. The parent owns spawn, private stdout/stderr captures, deadlines, signals and reap.

Probe argv is exactly `--nonce HEX48 --name example.com`. The probe makes one actual `getaddrinfo("example.com", "80", hints)` call with AF_INET, SOCK_STREAM and AI_NUMERICSERV. It does not fork, retry, issue its own DNS query, call a substitute resolver or choose a TCP endpoint. A bounded traversal preserves the returned order and duplicates; every node must have the selected Darwin AF_INET/TCP/port80/sockaddr_in16 shape. Cap32 and cycle checks precede traversal of another node. Only a complete valid chain is passed to freeaddrinfo; broken/cyclic/overcap chains fail and process teardown reclaims their memory.

Output is one compact ASCII JSON line followed by LF, at most8192 bytes, in this exact key order:

```json
{"version":1,"nonce":"0123456789abcdef0123456789abcdef0123456789abcdef","name":"example.com","pid":14,"status":"PASS","gai_rc":0,"system_errno":0,"error":"none","address_list_complete":true,"addresses":["104.20.23.154","172.66.147.243"]}
```

That is a synthetic format example, not a lookup result. `gai_rc` is signed32; `system_errno` is captured only for EAI_SYSTEM (selected SDK11), otherwise0. Error tokens are `none`, `gai_error`, `empty_result`, `address_shape`, `address_cap`, `address_cycle`, `unexpected_failure_result`. A failed result may retain a validated address prefix, with address_list_complete=false. Invalid CLI returns2 without JSON; setup/output failures return1 and can produce no complete line. Parent qualification requires full JSON, matching fresh nonce/PID, PASS, rc0/errno0/errornone/complete=true/nonempty list and actual process exit0. Output is one writer's framed stream, without a claim of multiwriter PIPE_BUF atomicity. Blocking getaddrinfo and pipe writes are bounded by the parent's deadline; the probe has no internal alarm or worker thread.

The returned order may differ from DNS RR order because libinfo sorts addresses. The parent must bind its chosen addresses[0] to the actual native TCP destination and a member of the independently validated DNS A RR set; do not require first wire A, silently sort, deduplicate or truncate. Probe PASS alone proves neither a fresh wire lookup nor external connectivity. The separately bounded backend retains destination policy.

Stage only the disposable RAM image: trusted `/var/run`, exact regular root-owned `/etc/resolv.conf` containing `nameserver 10.0.2.3\n`; `/etc/mdnsd.conf` absent or independently exact empty, and no preexisting `/var/run/mDNSResponder` or `/var/run/mDNSResponder.pid`. Pinned mdnsd unlinks UDS before bind, and opens PID file with `fopen("w")`, so exclusive context and absence checks are mandatory. Endpoint creates socket mode0777 via temporary umask0; PID mode follows inherited umask. Daemon may drop to nobody. On SIGTERM/INT the main loop returns EINTR4 after mDNS_Close/udsserver_exit; endpoint/PID unlinks can fail without changing that return. The parent must reap the owned positive PID and perform identity-checked leftover cleanup/absence verification. Never infer file cleanup solely from rc4 or kill a cached PID after reap.

Use a fixed child environment: no DNSSD_UDS_PATH endpoint override or SYSINFO_CONF_ENABLE module override. Existing account files may determine nobody; they are not written by this leaf. Selected POSIX daemon reads resolv.conf itself, so configd is not required. General configd-managed networking is separate work.

Source facts: AF_INET selects only A; libinfo uses DNSServiceQueryRecord with shared connection, ReturnIntermediates and Timeout. Normal unicast question is RD, one A/IN example.com question, generated nonzero DNS ID, no OPT addition on this path; retries use the core's source-generated ID/timers. The daemon's IPv4 query socket is ephemeral and shared across questions. Actual build has HAVE_IPV6 undefined. POINTOPOINT utun is excluded from multicast interface enumeration; lo0 is fallback, so local announcements/goodbyes should remain there. Daemon can call UDP connect to1.1.1.1 merely for getsockname, without a payload; a route clone can arise and must disappear with the owned interface. These are source expectations, not captured traffic.

Replay pure classifiers with `python3 -B integrations/puredarwin/m1-network-native-resolver/test_host.py`. Build recipes use the exact e7 pin offline and retained libSystem9fc. Artifact validation only reads Mach-O/source/export bytes. Root owns integration, SDK packet admission, target execution and verified Linux recovery. No system-resolver or persistent-network success is claimed here.
