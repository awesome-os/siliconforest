# Private native backing ownership

This original source implements a bounded ownership manager and a separate
IOKit API adapter for three private16KiB root/leaf/data buffers per job. It is
not a DART driver, hardware lifecycle, firmware loader or boot experiment. No
MMIO, publication, interrupt, activation, unmap or exposed-release API exists.
Hardware STOP, GPU HOLD and the shared PHY/PMGR write gates remain unchanged.

The design is `bcm4378-native-backing-provider-design-001.json` (SHA256
`3e627305b7d20e64f6a35b133a3421541a17c25b4c147e4cf1b42a03fcf866e1`),
direction-reviewed by `backing-provider-design-independent-review-001.json`.
The frozen private lifecycle C files are linked without modification through
`lifecycle_bridge.h`, which supplies external-C linkage to C++ callers.

## Files and boundaries

`backing.c` owns the original bounded state machine. It uses one caller-owned
boot-lifetime manager, four jobs, twelve native object slots, a copied trusted
policy, generation-checked tokens, monotonic handle/call identities and a short
mutex. It allocates nothing and never dereferences a buffer CPU address. Its
injected boundary receives one exact action and must echo the job/generation/
sequence/role/action on return. This is a trusted provider interface, not a
security boundary against a malicious callback or arbitrary memory corruption.

`native_iokit.cpp` is the genuine pinned-API implementation of that boundary.
It explicitly selects C++17 shared OSPtr mode and asserts the factory's actual
shared return type. Each returned reference moves directly into an independent
heap `NativeAnchor` field before explicit prepare/query/failure return. The
anchor is held by a permanent static pointer, has a deleted destructor and no
delete/unload API. Its descriptor fields are not members of a disposable facade.
Dropping a caller token cannot release them. Integration must keep this code and
anchor alive for the whole boot; this standalone artifact is not an unloadable
service or a mechanism that prevents an external module loader from misbehaving.

Native allocation calls the static `inTaskWithPhysicalMask(kernel_task,
kIODirectionOutIn | kIOMemoryMapperNone | kIOMemoryHostPhysicallyContiguous,
0x4000,0xfffffc000)`. Both runtime `PAGE_SIZE` and `page_size` must be16KiB.
The mask derives16KiB alignment and a conservative36-bit last byte; it is not
an IOVA or DMA authority. The native constructor's internal AutoPrepare is a
separate XNU-owned baseline. Exactly one additional provider-owned OutIn prepare
is tracked per descriptor; only its known successful pair is explicitly
completed. No private wire-count fields are accessed.

## Trusted two-phase control setup

The initial source design was refined before implementation freeze, without
changing that design receipt. A one-shot configuration supplied before a new
anchor existed could not describe its actual protected physical backing.

1. `bpn_native_pin_empty` runs once, at trusted single-threaded boot setup. It
   pins an empty typed anchor and native mutex and returns only a setup identity,
   generation, exact typed anchor CPU extent and opaque mutex address identity.
   It allocates no backing descriptors and exposes no descriptor/buffer view.
2. Platform setup must independently derive complete protected physical/control
   metadata, then call `bpn_native_configure` with the exact returned identity.
   A bounded nonempty CPU list, bounded nonempty36-bit PA list, nonzero provenance
   label and explicit completeness assertion are mandatory. They are copied;
   every returned descriptor PA/CPU span is actually checked against them.
   Invalid pure configuration leaves the zero manager unconfigured and may be
   corrected. Successful configuration happens once; no reset/reinit follows.

Those inputs are a trusted platform obligation, not proof generated by this
manager. The full typed anchor CPU extent is independently excluded even if the
supplied lists omit it. Opaque IOLock allocation extent and complete physical
control coverage are not discovered or guessed. Its returned address is not a
size claim. There is no `vtophys`, `pmap_find_phys`, kernel-pmap or unsupported
translation helper. No current platform helper supplies that complete
provenance, so real setup remains unready until separately reviewed derivation
exists. CPU alias checks never substitute for protected PA data. Native opaque
object allocator correctness remains part of the trusted platform boundary.

## Acquisition and CPU-private work

The manager reserves the frozen core lease and job before native calls. All
three nonnull returned references must be independently anchored and distinct
before any explicit prepare. Each native operation is marked in progress under
the short mutex, then runs outside it. Other acquisition/mutation/retirement
calls return BUSY, including same-thread callback reentry. Inspection copies
bounded metadata only. A hung call retains the busy state; there is no timeout
cancellation, worker reset or concurrent cleanup escape.

After three successful explicit prepares, actual length, capacity, CPU view,
physical segment length and MapperNone source PA are queried. All lengths must
be exactly16KiB; full aligned CPU/PA spans,36-bit last byte, descriptor identity,
protected spans, RAM/reservations, within-job and cross-job disjointness must
pass. The core must accept the complete derived root/leaf/data triple before
the provider can zero or copy. Numeric IOVA remains only a private reservation.
Permissions are explicit READ/WRITE; no execute or unknown bits are accepted.

Successful acquisition returns VALIDATED, not DMA_READY. `zero_private` first
requeries all three native views and checks unchanged private history, then
zeros exactly the three pages. Only INITIALIZED jobs accept bounded data-role
copies; no arbitrary root/leaf write API exists. Source bytes must be accessible,
immutable for the full call, and disjoint from anchor, protected controls and
every retained known buffer. These are CPU-private writes, not firmware or
page-table publication. Constructor-internal initialization precedes any returned
reference and is outside the provider-before-zero assertion.

## Failure, retention and retirement

A returned NULL allocation can retire an untouched private lease and then reset
earlier references without any explicit complete. A known post-prepare query,
validation or binding refusal can clean up only through the same ordered private
completion path. Every failed/unknown explicit prepare retains the entire cohort
and claims without a guessed compensating complete. Wrong operation identities,
unexpected core history and uncertain zero/copy also retain failure.

Retirement keeps claims live and every reference anchored while attempting one
complete per owned, unbalanced pair in reverse data/leaf/root order. The first
non-success, unknown or stale result stops cleanup; previously completed
descriptors are retained too, and no retry follows. Only after every needed
complete succeeds may `bpl_retire_private` invalidate the metadata lease. Only
after that may CPU views be cleared and native strong references reset. Return
from reset is recorded separately; it is not a physical drain/free attestation.

Every quarantine permanently halts the whole manager, preventing new acquisition,
CPU writes or further retirement, including work on other jobs. Previously bound
views may have changed and cannot justify further overlap admission. Inspection
remains available, and the first error stays recorded. Earlier reset references
may already be gone after reset uncertainty; the code does not claim otherwise.
No slot/claim reuse follows. There is no force release, unload, exposed retirement
or owner-wide memset recovery API. BUSY with halted=1 means this permanent domain
stop, not an invitation to retry. Other jobs' surviving references remain held.

`inspect` reports bookkeeping: identity records and reset-return counts may not
equal current strong-reference counts after an unknown call. Tokens, identities,
statistics and source compile results are not reusable hardware authorization.

## Tests and build evidence

Run `python3 -B integrations/puredarwin/m1-apcie-bridge/native_backing/test_backing.py`.
The manager tests link the unchanged lifecycle core and use actual fake object
references, constructor wire baselines and explicit pair counters. They check
calls outside the mutex, reentry, a blocked callback with a concurrent caller,
cohort retention, stale replies/tokens, bounds, overlaps, protected spans,
known-failure cleanup, before/after native-state failures, and release ordering.
Fixtures are disposed only by the test harness between cases; this is not a
production recovery path. Counter seeding is explicitly test-only.

`test_sdk/` contains original API-shaped test stand-ins, never production headers.
They compile and execute the actual adapter control flow with real fake strong
reference destruction. This tests direct anchor transfer, factory arguments,
two-phase setup, prepare failures, completion failures and facade independence;
it is not native IOKit execution. Compiled manager and native-adapter mutants
must build cleanly and then fail assertions. Assertion-disabled test builds
are refused. ASan/UBSan run with leak detection disabled because boot anchors
are intentionally retained. No SDK stand-in is used in the parent's genuine
cached-SDK build.

The parent separately owns the exact frozen-source ARM64 SDK compilation,
mixed C/C++ link, import and stack-frame receipt. Neither that compile nor these
host tests admits a private runtime allocation experiment, hardware work or a
boot packet. All predecessor source and receipts remain unchanged.
